# 사전등록: 장기 일봉 당일(시가→종가) 거래 선별 v1 — 방법 묶음 A

작성 2026-10-12 · 상태: **초안 1(독립 리뷰 전, 고정 전).** 이 문서의 어떤 후보도 손익을 계산한 적이 없다(§5.2). 고정 뒤 바꾸면 v2.
로드맵: 단계 3(사전등록 검증) 안의 "비용을 넘는 우위가 있는 새 일중 신호 연구". 데이터 기반은 `DATA_LONGHIST_V1.md`(PR #198).
설계: 사용자 결정 2026-10-12 — 새 탐색 방법을 모두 진행한다. **이 문서 = 묶음 A**: ① 장기 일봉으로 당일 거래 선별, ② 상태 조건 규칙,
③ 달력·이벤트 규칙, ⑤ 장중 대 밤사이 분해. **④ 변동성 기반 크기 조절과 ⑥ 머신러닝 결합은 이 문서 밖의 별도 사전등록이다.**
근거 표시: **(R)** 공개 연구(주장 요지만, 수치 인용 없음) · **(D)** 이 저장소 데이터·코드 사실 · **(J)** 판단.
이 문서는 읽기 전용 연구이며 주문·Paper 규칙 변경·실계좌·봉인 개봉을 승인하지 않는다.

## 1. 질문과 배경

조건 하나(상태·달력·이벤트)가 맞는 날 **시가에 3배 ETF를 사서 그날 종가에 파는 거래**가, 비용 왕복 0.20%를 뺀 뒤 거래당 평균 순수익 > 0인가.
- 왜 일봉인가(D): 1분봉 연구 둘(진입 v1·추세 전환 v1)은 자료가 약 2.5년뿐이라 우연과 구별되는 최소 우위가 거래당 0.7~2%였고 둘 다 `NO_PASS`였다.
  일봉은 지수별 8~21년의 개발 구간을 주므로 같은 기준에서 0.2~1%까지 내려간다(§6).
- 계좌 시뮬레이션(크기·하루 손실 한도·Charter §2의 USD 2,000 시작점 반복)은 하지 않는다(J: 우위만 분리). 크기 조절은 방법 ④ 사전등록에서 한다.
- 참고 연구(R, 조심해서 요약): Lou, Polk & Skouras 2019 JFE — 주식 수익이 밤사이(전일 종가→시가)와 장중(시가→종가)에 다르게 나뉘며 효과마다 나는 시간대가 다르다.
  Lucca & Moench 2015 JF — 1994년 이후 정례 FOMC 발표 전 약 24시간 동안 미국 주가지수 초과수익이 컸다. Baltussen, Da, Lammers & Martens 2021 JFE — 헤지 수요(딜러 감마)가
  음일 때 장중 모멘텀이 강했다. Ariel 1987, Lakonishok & Smidt 1988 — 월말·월초와 공휴일 전날 수익이 평소보다 높았다는 보고. 이 연구는 그 결과를 **재현하지 않는다**.
  같은 날 시가→종가라는 다른 단위로 바꿔 시험할 뿐이고, 결론은 이 데이터와 이 비용에서만 말한다(J).

## 2. 상품·거래 단위·수익 계산

| 기준 지수(신호·합성) | 롱 → 매수 | 숏 → 매수 | 실제 ETF 자료 시작(D) |
| --- | --- | --- | --- |
| SPY | SPXL | SPXS | 2008-11-05 / 2008-11-19 |
| QQQ | TQQQ | SQQQ | 2010-02-11 |
| ^SOX | SOXL | SOXS | 2010-03-11 (추종 지수 변경 이력 미검증, D: DATA_LONGHIST §4) |

- **거래 단위 = 세션 하나.** 그날 시가에 사서 그날 종가에 판다(조기폐장일은 13:00 종가). 한 후보 × 한 날에 거래 최대 1번. 후보끼리 서로 영향 없음.
- 기호(D, Yahoo `close` = 분할만 반영한 원종가, `adjclose`는 쓰지 않음): 세션 d, 직전 NYSE 세션 p(d)(`norm/calendar/nyse_sessions.csv`), 지수의 `O_d, H_d, L_d, C_d`.
  지수 장중 수익 `i_d = C_d ÷ O_d − 1`.
- **합성 3배 ETF 수익(판정용):** 롱 `R = +3 × i_d`, 숏 `R = −3 × i_d`. R < −1이면 −1로 자른다(J, 사실상 발생 없음).
- **순수익(Charter v2.4 §3):** `net = (1 + R) × (1 − c − f) − (1 + c)`, f = SEC fee 0.00206%(매도에만, D). 가격 불변 시 왕복 비용:

| 비용 세트 | c(편도 수수료) | 슬리피지 | 왕복(R=0) | 용도 |
| --- | --- | --- | --- | --- |
| 기본 | 0.10% | 0 | 0.2021% | 판정 |
| 스트레스 | 0.15% | 0 | 0.3021% | 판정(§7.3 ③, §8) |
| 민감도 | 0.05% | 0 | 0.1021% | 보고만 |

- **실제 ETF 대조(보고만, 선택·판정에 쓰지 않음):** 실제 ETF 자료가 있는 날(2010년 이후 DEV, HOLDOUT 전체)에 같은 비용으로 ETF `C ÷ O − 1` 순수익을 같이 계산해
  후보별 평균·합성과의 상관·평균 차이를 낸다. 일일 재조정을 반영한 합성 `R* = 3 × (1+g_d) × i_d ÷ (1 + 3 × g_d)`(롱, 숏은 −3)도 보고만 한다(J: 시가 시점 실제 노출 보정).
  실제 ETF 평균 순수익이 기본 비용에서 ≤ 0인데 합성이 통과하면 `FIDELITY_WARN`을 붙이고 다음 단계(1분봉 체결 점검)가 원인을 설명해야 한다.
- **알려진 한계(J):** 시가를 신호(갭)와 체결가에 같이 쓴다. 실제로는 개장 직후에야 갭을 알고 사므로 체결가가 다르다. 이 차이는 HOLDOUT 통과 뒤 1분봉 체결 점검(§9)이 잰다.
  ETF 운용보수(연 약 1%, 하루 0.004% 수준)는 넣지 않는다.

## 6. 실행 전 집계 (손익 없음) — 사용자 보고 후 "돌린다 / 멈춘다"

precount는 고정 뒤 구현으로 다시 계산해 `precount.json`에 쓴다: 후보별 DEV n, 반쪽별 n, 정의 안 된 날 수, 제외 사유별 수, HOLDOUT의 달력·이벤트 후보 날짜 수(coverage),
상태 후보의 HOLDOUT 예상 n(= DEV 비율 × HOLDOUT 세션 수, HOLDOUT 가격은 읽지 않음), 그리고 검정력.
sd는 DEV 적격 세션의 `3 × i_d` 표준편차(ddof=1, `purpose="performance"`, DEV 날짜만)다. 변동성만 드러내고 후보 손익은 드러내지 않는다.

**미리 계산한 값(D, 2026-10-12 스크립트):** sd = SPY 3.126%, QQQ 4.913%, ^SOX 4.933%. HOLDOUT 세션 2,399(세 지수 모두 coverage 행 2,399).
HOLDOUT 날짜 수: 월 446·화 494·수 491·목 485·금 483, 월말·월초 459, 공휴일 전날 89, 옵션 만기 115, 분기말 38, FOMC 75, FOMC 전날 75, CPI 106, NFP 111. GEX: DEV 1,930일, HOLDOUT 1,645일.

**잡을 수 있는 최소 거래당 평균 순수익(80% 검정력)** `δ = (z_{1−α} + z_{0.8}) × sd ÷ √n`. DEV는 BH 최악 단계 α = 0.10/156(계수 4.062), HOLDOUT은 Holm 첫 단계 α = 0.05/5(계수 3.168, sd는 DEV 값으로 대용 J).

| 경우 | SPY | QQQ | ^SOX |
| --- | --- | --- | --- |
| DEV C01(모든 날) | 0.18% | 0.31% | 0.45% |
| DEV 20% 조건(C15·C16) | 0.40% | 0.70% | 1.00% |
| DEV FOMC(C26) / C06 | 0.99% / 1.15% | 1.73% / 1.83% | 걸러냄 / 1.81% |
| HOLDOUT 모든 날 / 요일(~480) / FOMC(75) | 0.20 / 0.45 / 1.14% | 0.32 / 0.71 / 1.80% | 0.32 / 0.71 / 1.80% |

**의미:** 상태·달력 후보는 거래당 약 0.3~1%, 이벤트 후보는 1~2% 이상의 우위만 우연과 구별된다. 그보다 작은 우위는 "없음"이 아니라 "확인 불가"로 보고한다.
BH는 진짜 후보가 여럿이면 문턱이 완화되므로 위 DEV 값은 보수적이다. 자동으로 다음 단계로 가지 않는다. 이 집계를 보고 조건·문턱·구간을 바꾸면 v2.

## 7. DEV 검정 (주 묶음 한 번, GEX 묶음 한 번)

### 7.1 통계 (의사코드)

```
for k in candidates (fixed order, prefiltered ones skipped but kept in index):
    x = net(base cost) of candidate k on DEV trade days, sorted by date; n = len(x)
    if n < 2 or sd(x, ddof=1) == 0: p[k] = None
    else:
        rng = numpy.random.default_rng(SEED(variant, k)); m_obs = mean(x)
        for b in 1..B (B = 10_000):
            starts = rng.integers(0, n, size=ceil(n/5))           # 거래 5개 연속 블록, 순환
            xs = concat(x[(s + j) % n] for s in starts for j in 0..4)[:n]
            m_star[b] = mean(xs)
        p[k] = None if var(m_star, ddof=1) == 0 else (1 + count(m_star - m_obs >= m_obs)) / (B + 1)   # 한쪽, H0: 평균 ≤ 0
BH (q = 0.10) over the K active candidates:                      # p = None 은 1 로 넣는다
    sort by (p, k) ascending; i* = max{ i : p_(i) <= i × q / K }; reject ranks 1..i* (없으면 0개)
SEED(variant, k) = 20261012 + 1000 × variant + k
    variant 0 주 DEV 기본 · 1 스트레스 · 2 민감도 0.10% · 3 실제 ETF 대조 · 10 GEX DEV · 50 주 HOLDOUT · 60 GEX HOLDOUT
```

- 블록 = 그 후보의 날짜순 연속 거래 5개(J, 이전 연구와 같음: 변동성 군집 반영). 반쪽을 넘나들 수 있다(DEV 하나의 연속 구간). 난수는 위 순서로만 뽑는다.
- 스트레스·민감도·실제 ETF·반쪽별·재조정 합성은 같은 계산을 **보고만** 한다(BH 묶음 밖).

### 7.2 DEV 통과 (후보마다, 모두 참이어야 `DEV_SURVIVOR`)

| # | 조건 | 경계 |
| --- | --- | --- |
| ① | BH(q = 0.10)에서 기각 | p = None이면 거짓 |
| ② | DEV n ≥ 100 | 100이면 참(사전 걸러내기와 같은 기준) |
| ③ | 스트레스 비용 평균 > 0 | 0이면 거짓 |
| ④ | 기본 비용 평균이 앞 반쪽 > 0 **그리고** 뒤 반쪽 > 0 (§3 나누는 날) | 반쪽 거래 0개면 거짓, 정확히 0이면 거짓 |

**순위와 M:** 통과 후보를 스트레스 t(`mean_stress ÷ (sd_stress ÷ √n)`) 내림차순 → n 내림차순 → 번호 오름차순으로 정렬해 앞에서 **최대 M = 5개**(J, GEX 묶음은 M_G = 2)를
HOLDOUT에 보낸다. 지수·조건이 겹치는 후보(예: C11과 C13)도 따로 센다(분산 규칙 없음, J). 통과가 0개면 그 묶음의 HOLDOUT은 열지 않는다(`NO_PASS`).

**7.3 보고(통과와 무관, `dev_result.json`):** 후보마다 n(반쪽별), 평균·중앙값 순수익(세 비용), 수익 거래 비율(진단), t, p, BH 기각 여부, 반쪽 평균, 실제 ETF 대조(겹친 날 n·평균·상관), 재조정 합성 평균, USD 700 환산(J, 이전 연구와 같은 명목).
지수별 방법 ⑤ 분해. 사전 걸러낸 후보와 이유.

## 8. HOLDOUT (묶음마다 한 번만)

- **부록 PR**(`docs/research/PREREG_DAILY_SAMEDAY_SCREEN_V1_HOLDOUT_ADDENDUM.md`, GEX는 `…_GEX_ADDENDUM.md`): 내용은 **오직** ① 선택된 후보 번호와 정의(§4 그대로),
  ② `config/daily_screen_v1.json`·`precount.json`·`dev_result.json`의 SHA-256, ③ manifest·events yaml SHA-256, ④ 고정 문턱 값. 규칙·문서 본문은 바꿀 수 없다. 병합 커밋 해시가 개봉 조건이다.
- **개봉 조건:** 부록 병합, 사용자 승인(`--i-have-user-approval`), 실행 시 위 SHA 전부 일치. 문턱은 DEV 값 그대로(HOLDOUT에서 다시 계산하지 않음).
- **검정:** 선택 후보마다 HOLDOUT 거래일의 기본 비용 순수익으로 §7.1과 같은 부트스트랩(variant 50/60). Holm을 선택된 m개(≤ M) 안에서: p를 오름차순(동률은 번호)으로
  `adj_(i) = max_{j≤i} min(1, (m − j + 1) × p_(j))`, p = None은 adj 1.
- **`HOLDOUT_PASS`(후보마다 모두 참):** Holm adj p **< 0.05**, n **≥ 50**, 스트레스 비용 평균 **> 0**. n < 50이면 `HOLDOUT_INCONCLUSIVE`. 같음은 모두 거짓.
- **보고만:** 깨끗한 부분 구간 2016-01-04~2023-04-10(§5.2), 2016~2020 / 2021~2025-07-18 두 부분, 실제 ETF 결과·`FIDELITY_WARN`, 민감도 비용, 방법 ⑤ 분해.
- 열고 나면 이 연구 묶음에서 HOLDOUT은 사용 완료다. 다시 열어 다른 후보를 시험하지 않는다.

## 열린 질문

1. GEX 묶음의 G03(하위 20% 분위)은 사용자 지정 밖의 추가(J)다. G01(GEX < 0)이 DEV n < 100으로 걸러질 가능성이 커서 넣었다. 빼려면 고정 전에 결정.
2. SOXL·SOXS 추종 지수의 과거 변경일을 검증하지 않았다(D: DATA_LONGHIST §4). ^SOX 합성과 실제 ETF 차이가 크면 실제 ETF 대조로만 드러난다.
3. SqueezeMetrics GEX·DIX가 사후에 수정된 값인지(발표 당시 값과 같은지) 확인할 출처가 없다. GEX 묶음 결과는 이 한계를 달고 보고한다.
