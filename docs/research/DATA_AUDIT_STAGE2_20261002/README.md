# 단계 2 데이터 점검 — 지수 ETF 장기 일봉·VIX·단기 금리·레버리지 ETF

작성일: 2026-10-02 · ROADMAP 단계 2 · 정책 정본: [Charter v2.0](../../PROJECT_CHARTER.md)

범위는 출처·기간·결측·조정 방식 확인이다. **수익률·낙폭·신호 성과는 계산하지 않았다.**
가격은 Toss 일봉의 조정 방식을 판정하는 비율 계산에만 썼고, 그 계산도 2026-01-20 이전만 봤다.

## 결론

아래 "1차 출처"·"대조 출처" 배치는 **assistant 제안**이다. 출처 선택(특히 비공식 Yahoo 사용)은 단계 3 사전등록 전에 사용자가 확정한다.

2000~2002와 2008의 레버리지 결과는 지수 일수익률 × 배수 − 보수·금융비용으로 가상 계산해야 한다.
그 계산식과 실제 ETF 대조 방법은 단계 3 사전등록에서 정한다.

## 발견 1. Toss 일봉은 배당 조정이 아니다

저장소 `candle_history`의 1d 봉은 모두 `adjusted=1`, `source=toss_backfill`이다. 이 플래그가 무엇을 조정했는지
지금까지 검증되지 않았다(PROJECT_STATUS 벤치마크 근거).

검증 방법: 2016-03-18~2026-01-20 공통 거래일(종목당 2,474일)에서 Toss 종가를 Yahoo 두 값과 나눴다.

| 종목 | Toss ÷ Yahoo 원종가(분할만 조정) | Toss ÷ Yahoo 조정종가(배당+분할) |
| --- | --- | --- |
| SPY | 1.000000 → 1.000000, 변동계수 1.2e-5 | 1.183 → 1.008, 변동계수 0.047 |
| QQQ | 1.000000 → 1.000000, 변동계수 0 | 1.076 → 1.003, 변동계수 0.020 |
| TQQQ | 1.000000 → 1.000000, 변동계수 5e-6 | 1.054 → 1.006 |
| SQQQ | 1.000000 → 1.000000, 변동계수 6.3e-5 | 1.330 → 1.039 |
| SOXL | 0.999982 → 1.000000, 변동계수 6e-6 | 1.100 → 1.001 |
| SOXS | 1.000000 → 1.000000, 변동계수 3.7e-5 | 1.207 → 1.032 |

- 원종가와의 비율이 10년 내내 1이다. 조정종가와의 비율은 배당이 쌓이면서 움직인다.
  2026-01-20의 비율이 정확히 1이 아닌 것(SPY 1.008)은 Yahoo 조정종가가 2026-10-01에 받은 값이라 그 뒤 배당까지 반영하기 때문이다.
- 비교 구간 안의 분할(Yahoo 이벤트): SQQQ 역분할 6회(2017-01-12 1:4, 2019-05-24 1:4, 2020-08-18 1:5, 2022-01-13 1:5,
  2024-11-07 1:5, 2025-11-20 1:5), SOXS 역분할 5회, TQQQ 분할 5회, SOXL 분할 1회(2021-03-02 15:1).
  분할 전후에도 비율이 1로 유지된다. 그러므로 **Toss `adjusted=True`는 분할 조정만 뜻한다.**
- 따라서 Toss 종가로 계산한 수익률은 배당을 빠뜨린다. 여러 날 보유 연구에서는 배당을 따로 더해야 한다.

## 발견 3. 접근성과 주의점

- **FRED는 이 Mac에서 내려받기가 실패했다**(`RemoteDisconnected`, curl exit 56·92). 같은 날 원격 WebFetch로는 열렸다고 보고됐으나
  저장한 파일이 없어 **미검증**이다: DTB3 1954-01-04~2026-09-30, DGS3MO 1981-09-01~, VIXCLS 1990-01-02~,
  SP500 2016-10-03~(라이선스상 10년, 장기용 불가). 그래서 단기 금리는 로컬에서 받을 수 있는 Ken French RF를
  1차 출처로 제안한다(assistant 제안). DTB3는 접근 문제를 해결하면 대조용으로 쓴다.
- **Yahoo는 비공식 API다.** 약관상 재배포가 금지된다. 원본 응답은 gitignore 경로에 두고 커밋하지 않는다.
  조정종가는 새 배당이 생길 때마다 과거 값이 다시 계산되므로 시점 고정값이 아니다. 내려받은 날짜를 기록하고
  원종가·배당·분할 이벤트를 따로 저장해 조정을 직접 계산한다.
- Yahoo의 원종가(`close`)도 분할은 이미 반영돼 있다. SQQQ·SOXS는 역분할이 8~10회라 과거 가격이 매우 크게 보인다.
- Stooq CSV는 키 없이 빈 응답, Nasdaq API는 시간 초과였다. 둘 다 키 없는 출처로 쓸 수 없다.
- 레버리지 ETF의 무료 대조 출처가 없다. 필요하면 운용사(ProShares·Direxion) NAV 이력을 확인한다.
- 새 유료 공급자 가입은 하지 않았다.

## 봉인 구간 접촉 기록

- Toss 조정 판정의 가격 비율은 2026-01-20 이전만 계산했다.
- Yahoo·Cboe 파일은 2026-10-01까지 내려받았고, 2026-01-21 이후는 **날짜 존재 여부만** 셌다(가격·수익률 미열람).
  기존 blind OOS(2026-01-21~07-21)·H2(07-22~09-30)의 coverage 정보는 "이미 본 정보"로 기록한다.
- 단계 3 사전등록은 개발/봉인 구간을 결과 전에 새로 정한다. 이 점검은 어느 구간의 수익률도 보지 않았다.

## 단계 3 사전등록에서 정할 것

1. 1차 데이터 조합(assistant 제안, 사용자 확인 필요): Yahoo(SPY·QQQ·지수·레버리지 ETF) + Cboe VIX + Ken French RF. Toss 일봉은 대조용.
2. 배당 처리: 원종가 + 배당 이벤트로 총수익을 직접 계산하고 `^SP500TR`과 대조하는 방법을 사전등록에 적는다.
3. 2006년 이전 레버리지 구간의 가상 계산식(배수·보수·금융비용·일일 리밸런싱)과 실제 ETF 대조 허용 오차.
4. 개발/봉인 구간과 하락장 4개의 배치.

## 재현

`probe.py`(내려받기·요약)와 `audit2.py`(달력 대조·Toss 조정 판정)를 같은 폴더에 두었다.
실행 결과 요약은 `probe_summary.json`, `audit2_summary.json`이다. 원본 내려받기 파일은 `ext/`에 쓰이며 커밋하지 않는다.
실행: 저장소 `.venv/bin/python`. `audit2.py`는 운영 체크아웃의 `data/market_history.sqlite`를 읽기 전용으로 연다.
